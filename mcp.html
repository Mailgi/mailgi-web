MCP server

Email for agents, as MCP tools

A hosted Model Context Protocol server at https://api.mailgi.xyz/mcp. Point Claude Code, Claude Desktop or Cursor at it and the agent can register an address, send, read and file mail — with nothing to install on the server side.

Streamable HTTP · Stateless · Headers for auth

https://api.mailgi.xyz/mcp
# headers decide which tools work

What it is

The MCP server runs inside the Mailgi API itself. Each tool forwards to an existing REST endpoint and returns that endpoint's response, so a tool call and the equivalent curl behave identically: the same validation, the same rate limits, the same metering against the same wallet. Nothing is cached or reshaped in between. The server is stateless — there is no MCP session to keep alive — and credentials travel as HTTP headers on the connection, not as tool arguments.

The server also exposes one resource, mailgi://skill, which serves SKILL.md — the plain-language guide to the API — so a client can load it as context without fetching the website.

Connect a client

Transport is Streamable HTTP. Already have an API key? Add it as the Authorization header and you're done. Don't have one yet? Start without headers and follow the bootstrap below.

Claude Desktop's config file only launches local processes, so it reaches a remote server through the mcp-remote bridge, which needs Node.js. Cursor speaks HTTP directly.

# With an agent API key
claude mcp add --transport http mailgi https://api.mailgi.xyz/mcp \
  --header "Authorization: Bearer amb_..."

# Org tools as well — add the dashboard session header
claude mcp add --transport http mailgi https://api.mailgi.xyz/mcp \
  --header "Authorization: Bearer amb_..." \
  --header "X-Mailgi-Session: <session token>"

# No credentials yet — public tools only, for bootstrap
claude mcp add --transport http mailgi https://api.mailgi.xyz/mcp
// claude_desktop_config.json
{
  "mcpServers": {
    "mailgi": {
      "command": "npx",
      "args": [
        "-y", "mcp-remote", "https://api.mailgi.xyz/mcp",
        "--header", "Authorization:${MAILGI_AUTH}"
      ],
      "env": { "MAILGI_AUTH": "Bearer amb_..." }
    }
  }
}
// The env indirection keeps the space in "Bearer amb_..."
// from being split when the arguments are passed on.
// .cursor/mcp.json (project) or ~/.cursor/mcp.json (global)
{
  "mcpServers": {
    "mailgi": {
      "url": "https://api.mailgi.xyz/mcp",
      "headers": {
        "Authorization": "Bearer amb_..."
      }
    }
  }
}

Bootstrap: from nothing to a key

The server has no OAuth, so a credential can't be attached to the connection for you. The agent obtains one through a tool, and a human puts it into the client config once.

01

An agent of its own

Connect with no headers and ask the agent to call register_agent (optionally with a label, or a domainToken and localPart to claim an address on a company domain). It returns the email address and an API key starting amb_ — shown exactly once. Re-add the server with Authorization: Bearer amb_… and the agent tools appear. In Claude Code that is claude mcp remove mailgi followed by the add command above.

02

Org admin, by emailed code

For the organisation tools — domains, members, registration tokens, the org wallet — the agent calls org_login_request_code with a human's email address. Mailgi emails that person a six-digit code; they tell the agent, which passes it to org_login_verify and gets back a dashboard session token. Add it to the connection as X-Mailgi-Session. Call org_logout to end that session when you're done with it.

03

Both at once

The two headers are independent. Send both and the connection has agent and org tools together — for example an admin agent that creates a registration token with regtoken_create and hands it to another agent to self-register on the company domain.

Limits, stated plainly

01

One config edit after bootstrap

A key obtained through register_agent or a session from org_login_verify doesn't attach itself to the connection. A human has to add the header to the client config and reconnect. Until then only the public tools work.

02

No OAuth, so no hosted connectors yet

claude.ai and ChatGPT add remote MCP servers as hosted custom connectors, which authenticate with OAuth rather than a header you type in. The server doesn't implement OAuth, so it can't be used from those today. Clients where you control the headers — Claude Code, Claude Desktop through mcp-remote, Cursor — work.

03

Org tools give an agent admin reach

A session token carries the signed-in human's role. An agent holding an owner's or admin's session can detach domains, remove members, revoke tokens and delete inboxes. The destructiveHint annotation only helps if your client asks before acting on it — only add X-Mailgi-Session to a connection you would trust with the dashboard, and end it with org_logout.

04

Same limits and prices as REST

MCP is not a separate tier. A mail_send is metered and rate-limited exactly like POST /v1/mail/send — see pricing — and errors come back as the endpoint's own error.

Not using MCP?

The same API is plain HTTP, a CLI and a TypeScript SDK, and SKILL.md teaches any agent to use it directly.
