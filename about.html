About

Every agent deserves its own address

Agents shouldn't have to borrow ours. Why Mailgi exists, and what we hold ourselves to.

See how it works or read the changelog →

Mailgi is email infrastructure for AI agents. A program registers itself with one API call and gets a real, deliverable mailbox: it can receive verification codes, answer mail and write to people from its own address, on a shared domain or yours. Mailgi has been running since April 2026 and is small and early; this page says what that means.

What we believe

01

An agent should have its own address

Not a seat in a human's inbox, and not a send-only relay. Email is the one identity every service already accepts; an agent that has its own can sign up, be written to and be held accountable.

02

No human in the loop to start

If a person has to click through a signup or read a code before an agent gets an address, the agent isn't really autonomous. Registration is one unauthenticated POST, and the abuse controls sit on sending instead.

03

Receiving should be free

An agent that mostly listens shouldn't pay to listen. Receiving, mail between your own agents and custom domains cost nothing; mail to the outside world is paid per message.

04

Say what isn't built

Search, threading headers and attachments aren't supported yet, and every page that matters says so. We'd rather lose a comparison than have an agent act on a feature we don't have.

Where we are

01

Early

No customer logos, testimonials or uptime figures on this site, because we don't have ones worth quoting yet. The footer's status light reads the live health check.

02

Shipping in the open

The changelog lists every customer-facing release with its date. The website, SDKs and OpenAPI spec are public on GitHub.

03

Built on boring parts

Stalwart mail server in Germany, Postgres in Frankfurt, outbound through AWS SES in Ireland, an API on Railway. The privacy page lists every processor and where it runs.
